# ADR 0001 — Tech Stack

## Status

Accepted (2026-11-16)

## Context

Solo-developer portfolio. Goal: demonstrate frontend architecture judgment.
Must be statically deployable to GitHub Pages today and a custom domain later.
Maintainable by one person. No backend, no CMS.

## Decision

- **Runtime:** React 19 + TypeScript (strict)
- **Build:** Vite 8
- **Routing:** React Router v7 (data mode) with lazy routes
- **Styles:** CSS Modules + CSS custom properties (design tokens)
- **State:** Zustand (theme + locale only; no server state)
- **Testing:** Vitest + React Testing Library (added in Phase 3)
- **Lint/Format:** ESLint 9 (flat config) + Prettier
- **Git hooks:** Husky + lint-staged + commitlint (Conventional Commits)
- **CI/CD:** GitHub Actions → build → deploy to GitHub Pages
- **Runtime Node:** 22.18.0 (see `.nvmrc`)

## Consequences

- Zero server runtime. Deploy anywhere static.
- Design tokens align with the portfolio's own narrative (design systems).
- Fast feedback loop; Vite HMR.
- `base` is environment-driven (`VITE_BASE_PATH`), so custom domain migration is a config change.

* No built-in image optimization (mitigated with `vite-imagetools` if needed).
* SEO requires manual meta management per route (acceptable for 5 routes).
* GitHub Pages does not support SPA fallback natively → we ship a `404.html`
  redirect shim generated by `scripts/postbuild-copy-404.mjs`.

## Alternatives considered

- **Next.js:** rejected. RSC/cache complexity unjustified for a static portfolio.
- **Astro:** rejected. Excellent for static, but the portfolio should also
  demonstrate React 19 + state + testing — the author's stack.
- **Tailwind:** rejected. CSS Modules + tokens demonstrate design-system
  control more directly, which is the portfolio's thesis.
- **oxlint:** rejected. Fast, but `jsx-a11y` support is immature and the author's
  CV declares ESLint. Accessibility is non-negotiable.
